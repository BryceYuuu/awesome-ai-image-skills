# Selection Criteria

This catalog is visual-first. A repository is not included merely because its README says “beautiful”, “professional”, or “editorial”.

## Required

1. A public GitHub repository with an identifiable author/source.
2. At least one real output/example image viewable from the repository or its README.
3. A clear use case related to image editing, image transformation, poster/card generation, editorial design, covers, or adjacent visual production.
4. Enough documentation to understand what the Skill actually does.

## Strong positives

- Source-photo preservation rules are explicit.
- The visual system has constraints, not just a bag of style adjectives.
- The README shows before/after examples or multiple outputs.
- Installation and runtime requirements are documented.
- The author explains quality checks, text handling, layout constraints, or failure modes.

## Reasons to exclude

- No visible examples.
- Mostly a fork/clone with no meaningful visual difference.
- Generic prompt dump with no repeatable workflow.
- “AI aesthetic” that relies on neon glow, random gradients, 3D plastic, or decorative clutter without a design rationale.
- Unknown provenance for the showcased images.

## Rating philosophy

This repository intentionally does not publish a numeric “beauty score”. Aesthetic judgment is subjective; the catalog instead exposes examples so readers can decide with their own eyes.
